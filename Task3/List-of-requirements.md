## Требования к реализации и безопасности:
1. Для авторизации и определения уровней доступа решено использовать имеющиеся в проекте базы данных. 
Т.е. для авторизации предлагается использовать уже имеющуюся систему авторизации auth-service-1 (у которого своя база данных с пользователями). 
Получать id от Keycloak и связывать данные из баз данных **db-of-faces** и **users-white-list-db** с id Keycloak (в качестве ключей)
2. В отдельную базу данных выносим биометрию пользователей, фотографии номеров машин и самих машин пользователей и связываем с идентификаторами из Keycloak. <br />
Приложение будет собирать следующие биометрические данные:
   + фотографии лиц (используются для верификации) для умного домофонона
   + данные с видео камер (для умного шлагбаума)
   Эти данные планируется хранить в базах данных сервисов и связывать их с id из Keycloak
3. Запросы к домофону и шлагбауму проходят через API Gateway, в котором осуществляется проверка JWT токенов
4. Для передачи данных между микросервисами системы планируется использование JWT
5. Для обмена данными **система --> пользователь** планируется использование протокола OAuth (на основе RBAC настроенной в системе)
6. Для получения доступа к системе со стороны партнёров так же будет применяться OAuth (в RBAC должны быть созданы, соответствующие, роли)

### Обеспечение соответствия 152-ФЗ:
1. биометрия и номера машин хранятся в зашифрованном виде
2. так же шифруются данные с видео камер и те данные которые могут позволить проанализировать привычки пользователей, их расписание и предпочтения
3. доступы разграничиваются с использованием ролевой модели (RBAC). RBAC - выбрана потому что проще в настройке и на основании описания системы я не увидела сложных, гибких ролей.
4. данные о пользователях будут храниться на серверах России
5. Все изменения персональных данных должны логироваться (временной меткой и идентификатором того кто изменил и какие поля) (на схему добавлена DB для логов)
